# PolyGlue

## Purpose and capabilities

PolyGlue is a planned Python interface compiler and source generator for typed, bidirectional interoperability between native and managed runtimes. The current development version is 0.0.1. The repository currently contains the specification, project documentation and original branding, not a working compiler or native runtime.

Read [PROJECT.md](PROJECT.md) before implementation. It defines product scope, all target languages and platforms, IDL semantics, module-first configuration, template overrides, ABI, native packaging, examples, test matrix and acceptance gates. Do not claim a planned capability has been implemented.

The compiler resolves logical symbols, module dependencies, type/ABI identities, naming, annotations, physical file plans and imports before rendering Jinja2. Templates render validated models and may be overridden per module and target. Preserve every configured lookup layer, including library and module target defaults. Deterministic generated files must not contain wall-clock timestamps or machine-specific absolute source paths. Concrete generic specializations must have one public artifact owner in the module dependency closure. No untrusted IDL can execute code or select arbitrary output paths.

The runtime implements shared ABI mechanics, ownership, references, buffers, async/callbacks, cancellation and optional registry. Apply the ownership matrix, host-specific release rules, weak proxy cache, borrow alias/lease rules, DataRef allocator provenance, memory domains and configurable resource budgets in PROJECT.md section 13. Never expose unrevocable managed borrowed views as safe APIs. Verify actual roots, pins, leases, pending dispatch, releases and copies, including partial failure and cross-runtime cycles. Review Djinni support sources and current host documentation during implementation; no dependency or compatibility layer. Generated adapters connect typed interfaces in both directions. Keep business logic in the consumer/provider implementations. Use one compatible runtime per execution context. Attach adapters only to a validated, initialized context. Never exchange handles across independent contexts. A shared explicit cancellation token may notify several operations, while cancellation of one operation does not automatically signal the shared token. Register cancellation observers without a lost-request race and remove them before freeing their contexts. Python is the build-time generator and orchestrator, not a required runtime in non-Python applications. Do not overwrite unowned outputs or leave a stale successful manifest after an incomplete generation. Detect manually edited manifest-owned files and require explicit owned regeneration authorization; verify content hashes before incremental reuse. Do not introduce mandatory JSON serialization, Protocol Buffers, network RPC or compatibility layers with other tools.

The type system supports built-in exact date, timestamp, duration and UUID values, with checked native conversions. Keep the built-in catalog limited to the specified common types and use external types or ordinary IDL for domain-specific values. External types use module-owned versioned descriptors, existing canonical ABI representations and explicit host-language adapters. Users must be able to add a type without editing or rebuilding the generator. Never silently truncate temporal values, invent a target mapping, evaluate descriptor code or use raw foreign pointers as integers. Follow the external type schema and tests in PROJECT.md.

Modules are the unit of logical generation. Libraries aggregate modules for unified public APIs and binary distribution without changing logical module identity. Mixed Apple frameworks expose one unsuffixed public module for both Swift and Objective-C (section 10.6.1); separate public modules are explicit. Apply concrete lowering/boxing/array/ownership rules in section 5.4.3. Use CMake for native code and the proper ecosystem tooling for Gradle, Apple, SwiftPM, Python, Dart/Flutter, .NET and JS/TS/WASM. **Public API ownership rule:** Apply PROJECT.md sections 4.6, 8.11, 10.6 and 18.19. Generator complexity must not leak into ordinary consumer/provider APIs. Static and instance calls use the declared public type name, not an extra static invocation type. Use native type tokens for registry resolution where available, typed facades and scoped provider roles only where necessary, and deterministic private allocation for internal proxies/adapters. Keep real ownership, context, cancellation and executor controls explicit; never create or guess a context. ### Cross-runtime semantic and memory gates

Apply PROJECT.md sections 5.4.4, 12.7–12.8, 13.6–13.8 and 14.4.1–14.4.4. Immutable value models must not expose mutable aliased value leaves; preserve reference capabilities and explicit ownership. Use canonical structural equality only where defined, distinguish payload-free business Result from optional absence and avoid vector<bool> raw-buffer assumptions. Detect recursive value graphs and compute fingerprints from a finite canonical descriptor graph. Freeze actual C/WASM ABI profiles, layouts, handle encoding and status values before claiming adapter compatibility. Allocation-independent status and pre-reserved cleanup are required; do not run a rejected thread-affine deleter on an arbitrary thread. Retire storage only after last owner and access lease, and retain executable code through pending cleanup. Safe allocations expose initialized bytes, mutable borrowed writes are not rolled back, aggregate budgets reserve before use. Capture async arguments before acceptance/publication, respecting explicit native lazy invocation semantics. Cancellation observation is not source authority; disposal is not cancellation. Own and explicitly dispose stream acquisition and subscription separately. Mixed Apple public imports use one unsuffixed module and one visible Swift contract, without conflicting imported/native protocols. Verify actual host-specific lifecycle evidence and document user ownership/cleanup per feature. Never mark a planned test passed.

### Execution domains and initialization

Follow PROJECT.md sections 5.4.5, 12.9, 14.7 and 17.2.1. Each concrete type has a construction, active-payload, move, release, host-affinity and transfer plan. Import never starts a runtime, pool or service. Initialize contexts/attachments transactionally, track Opening rollback against parent shutdown, preserve failed cleanup control and never infer a business start/stop method from its name. Bind actual host executors explicitly; owner/main/named affinity is validated at generation, registration and invocation. Async is not a thread, and no per-call worker or implicit pool is allowed. Prefer native nonblocking I/O; blocking I/O/CPU work uses an explicit bounded executor. Preserve caller/provider/transport/completion/cleanup domains independently. Never queue-and-block to fake sync across an actor, isolate, loop or thread. No foreign code, scheduler enqueue, cleanup or await under core locks. Reserve before publication; keep required cleanup and completion paths accountable even when business queues are saturated. Test initialization rollback, actual executor identity, reentry, cancellation and HTTP responsiveness using deterministic local fixtures. Borrowed executors are not stopped by attachment disposal; owned executor shutdown follows actual work/release drain. Explicitly document actual platform support, not inferred behavior from async syntax.

### Application-owned threads and native entry

Follow PROJECT.md sections 14.7.5–14.7.8. Support threads, queues and workers created by the embedding application; valid synchronous native entry stays on the caller's OS thread and does not create another context or worker. Default bound_serial is not arbitrary-thread permission. Expose explicit bound_concurrent and direct_any_thread capabilities only when actual provider/host safety is proven; main/named affinity cannot be overridden. No mandatory registration per pure native thread; actual JNI/interpreter/ARC/CLR/JS/isolate entry rules still apply. Validate and pin actual call lifetime before entry, not just wrapper identity. Do not move host wrappers across isolation without a proven owning transfer; reverse callbacks have independent affinity. Never silently queue-and-block a synchronous call, including void callbacks. Allow deliberate blocking native I/O on permitted application workers, and keep the portable HTTP contract genuinely async. Worker exit is not automatic cancellation or attachment close; borrowed workers remain application-owned. Test direct and rejected synchronous paths, reverse callbacks, actual executor identity, cancellation/close races, thread reuse and explicit cleanup for every supported language and platform.

## Ownership, security and privacy

Name the owner of every task, callback, registration, subscription, native handle, allocation, buffer and lock. Validate sizes, alignment, ranges, encodings, handles, ABI compatibility and caller/runtime origin at the real boundary. Never return dangling references or silently replace failure with empty/success. Distinguish expected Result failures, runtime errors, absence, cancellation and successful empty values.

No exceptions cross ABI. No foreign callback, scheduler or deleter runs while internal locks are held. Establish lock ordering, exactly-once terminal state, shutdown behavior, cancellation and actual execution lifetime. Cancel does not prove foreign work stopped. DataView and MutableDataView are direct synchronous parameter-only borrows. Reject stored, returned and async borrowed values. DataRef is an owning reference. Validate handles against runtime-owned metadata and acquire their live references atomically. Preserve separate logical, semantic contract, boundary ABI and public artifact fingerprints; reject generation wrap/reuse and incompatible descriptors. Caller cancellation does not end provider execution. Drain operations, remove registrations and invalidate handles, then drain the releases caused by those actions on live owning executors before detaching a runtime. Keep cleanup available when business calls are blocked. Do not allow a borrowed view to become DataRef unless its true owner can be retained with a legal independent lifetime. Copies must be explicit. Ordinary value types and collections do not promise shared identity. Never claim zero-copy without appropriate evidence. Check portable key equality (exact Unicode scalar sequence, identical allowed set elements/map keys) and distinct optional states across runtimes. Use the portable Dart BigInt int64/uint64 profile by default on all platforms; native-only signed int64 as int is explicit opt-in. Distinguish owning stream acquisition from subscription. Ordinary user interface release must not infer a cancel method. Completion tokens remain valid until actual provider ownership ends. Scoped callbacks cannot extend admission beyond actual enclosing execution. Static operations use explicit typed bindings, not the registry stack. A synchronous callback, including one returning void, must finish in its allowed calling context. Only explicit async callbacks can queue owning arguments for later execution. Never implement synchronous Dart callbacks with an asynchronous NativeCallable.listener. Reject borrowed values in async dispatch. Initialize completion state before starting foreign work and retain start-call references through inline completion. A lossless stream obeys demand, drains accepted values on normal end and releases pending values on cancellation or failure. An empty stream can complete before the first item. Check reentrancy and race conditions even in managed runtimes.

Treat IDL, YAML, manifests, native inputs, external SDK output and package archives as untrusted data. Templates and implementation build extensions are explicit trusted developer input.
